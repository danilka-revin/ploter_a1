# JBD BMS — чтение и прошивка

Кроссплатформенная программа для Windows и Ubuntu: читает данные с платы BMS JBD / Xiaoxiang / Overkill Solar по UART
(последовательный порт 9600 8N1) и показывает их в браузере на локальном адресе.
Оформление и механизм обновления из GitHub такие же, как в проекте
[linux_pcb_app](https://github.com/danilka-revin/linux_pcb_app).

> **Прошивка.** Экран «Прошивка» проверяет файл `.hex` (разбор, адреса, контрольные суммы,
> размер, SHA-256). **Запись в плату пока отключена**: открытого протокола загрузки прошивки
> по UART у JBD нет в открытом доступе, поэтому кнопка «Записать прошивку» заблокирована.
> Запись появится после того, как будет подтверждён протокол загрузки (см. раздел «Что нужно,
> чтобы включить прошивку»).

## Что умеет

**Одна большая панель на весь экран** — без прокрутки страницы и без «сайта из вкладок». Плитки
заполняют окно, прокручивается только содержимое самой плитки. Данные живые: опрос раз в секунду
(период меняется в шапке), графики строятся по накопленной истории, при потере связи плитка
краснеет, а банк помечается «нет связи».

| Область панели | Что показывает и чем управляет |
|---|---|
| Шапка | имена и состояние всех банков, чипы-итоги по парку (напряжение, суммарный ток и мощность, средний SOC, разброс ячеек, максимальная температура, активные защиты), окно графиков (2/5/15/60 мин), период опроса, выгрузка CSV и JSON, плотность, тема, во весь экран, проверка обновлений |
| Отчёт по всем банкам | таблица: банк, порт, В, А, Вт, мАч, SOC, циклы, мин/макс/разброс ячеек, температуры, ключи, защиты, мини-график; клик по строке выбирает банк, «⌄» — переименовать, переподключить, отключить |
| Ключевые числа | крупные значения выбранного банка (или парка): напряжение, ток, мощность, остаток, разброс, температуры, циклы, шкала SOC и счётчики защит |
| Графики | напряжение и ток на двух осях, мощность с порогом нуля, температуры по датчикам (пороги перегрева/переохлаждения штриховыми линиями), разброс ячеек с порогом балансировки, остаток заряда, полоски напряжений ячеек и лента событий |
| Плата: все данные и настройки | три вкладки. **«Все данные платы»** — регистр 0x03 целиком (напряжение, ток, остаток, циклы, дата, ключи, балансировка, 13 битов защит, счётчики 0xAA, паспорт 0x06–0x09/0x0A/0xA0–0xA2) и все 59 регистров EEPROM как они прочитаны. **«Защита и настройки»** — то же самое в виде формы записи: счёт вносимых изменений, метки «риск» и «старший/младший байт», разбивка по группам, побитовый разбор масок. **«Прошивка»** — версия из 0x03, проверка `.hex` |
| Управление | ключи заряда и разряда, балансировка, остаток ёмкости, сброс счётчиков защит, пересчёт SOC, мягкая перезагрузка; режим «всем банкам сразу»; резервная копия и восстановление настроек |
| Консоль регистров | произвольное чтение (до 160 регистров за раз) и запись одного регистра, каталог всех регистров платы с группировкой и пометкой опасных, вход в заводской режим |
| Подключение | список портов (занятые банками помечены), «Найти и подключить все» (опрос всех портов, подключает только ответившие), «Демо-банки» 1–6, добавление банка вручную, инструкция «как найти порт» |
| Подвал | состояние опроса, число банков и период, последняя строка журнала; клик — журнал событий всего |

Горячие клавиши: **F** или **F11** — во весь экран, **D** — демо-банки, **S** — найти и подключить,
**J** — журнал, **1…9** — выбрать банк, **Esc** — закрыть окно.

Всё, что плата отдаёт по UART, видно на панели; всё, что можно записать, записывается отсюда же:
59 регистров EEPROM (пороги, токи, температуры, ёмкость, таблица SOC, задержки срабатывания и
возврата, маски функций и датчиков, время ключей и индикатора), два регистра управления
(0xE0 остаток ёмкости, 0xE1 ключи), 0xE2 балансировка, 0x0A пересчёт SOC, 0xE3 перезагрузка.
Число ячеек, пароли и калибровочные поправки из приложения не меняются.

Данные обновляются автоматически, пока платы подключены. Список портов обновляется сам, когда вы
вставляете адаптер. Как понять, к какому порту подключена батарея, — см.
[`docs/kak-najti-port.md`](docs/kak-najti-port.md).

## Несколько плат одновременно

Каждый **банк** — это отдельная плата BMS на своём UART-адаптере. Банки опрашиваются параллельно,
у каждого своя история, свои настройки и свои команды.

- добавить банк: «Подключение» → выбрать свободный порт и «Подключить», либо «Найти и подключить
  все» — программа опросит все порты и подключит только те, где ответил BMS;
- без платы: «Демо-банки» — 1…6 эмуляторов с разной химией и числом ячеек (8S, 12S, 16S);
- банк можно переименовать («Гараж · 12S») — имя попадёт в отчёт, CSV и журнал;
- «весь парк» в списке банков — графики и числа по сумме всех банков: суммарные ток, мощность и
  ёмкость, среднее напряжение и SOC, минимальная и максимальная ячейка, максимальная температура,
  число банков без связи;
- команда с переключателем «всем банкам» уходит сразу на все подключённые платы, а отказ одной
  не мешает остальным;
- банк без ответа трижды подряд помечается «нет связи», порт не закрывается — опрос продолжится.

Переменные запуска: `BMS_APP_HOST` (по умолчанию `127.0.0.1`), `BMS_APP_PORT` (8585),
`BMS_POLL_MS` (1000), `BMS_DEMO_BANKS` (сколько демо-банков поднять без платы),
`BMS_AUTOCONNECT` (1 — при старте опросить все порты).

## HTTP API панели

Сервер отдаёт интерфейс и JSON; всё то же самое можно читать и писать из своего скрипта.

| Запрос | Что делает |
|---|---|
| `GET /api/panel?focus=<id>&window=300` | строки всех банков, итоги парка и ряды графиков — один запрос на весь кадр |
| `GET /api/banks`, `GET /api/history?id&window` | список банков; история одного банка |
| `GET /api/bank/registers?id` | базовая информация, ячейки, счётчики, паспорт и все настройки банка |
| `GET /api/catalog` | каталог регистров, настроек, команд и защит (то, что знает программа) |
| `GET /api/report?id&settings=0`, `GET /api/report.csv` | отчёт по всем банкам в JSON и CSV (разделитель `;`, RU-запятая) |
| `POST /api/banks/add` `{path,label}` / `remove` / `rename` / `reconnect` | банки |
| `POST /api/banks/auto` `{force}` / `POST /api/banks/demo` `{count}` | автоподключение всех портов / демо-банки |
| `POST /api/poll` `{ms}` | период опроса |
| `POST /api/bank/settings/write` `{id,changes,confirm,risk,save,password}` | запись настроек; без `confirm` отказ, `risk` обязателен для рискованных регистров |
| `POST /api/bank/control` `{id,action,...,confirm,all}` | ключи, балансировка, остаток, сбросы (`id: "all"` — всем банкам) |
| `POST /api/bank/raw/read` `{id,regs}` / `POST /api/bank/raw/write` `{id,reg,raw,confirm,risk,factory,password}` | консоль регистров |
| `GET /api/backup?id`, `POST /api/backup/restore` `{id,file,dryRun,confirm,risk}` | резервная копия и восстановление |
| `GET /api/state`, `/api/snapshot`, `/api/ports`, `/api/scan`, `/api/settings/write`, `/api/control/*` | старые одиночные адреса, работают с первым банком |
| `GET /healthz`, `/api/version` | проверка живости и версия |
| `POST /api/firmware/inspect` / `/api/firmware/flash`, `/update/check`, `/update/run` | прошивка (запись отключена) и обновление с GitHub |

## Подключение платы

Нужен USB–UART адаптер (CP2102, CH340, FTDI и т. п.).

| Адаптер | Плата BMS |
|---|---|
| RX | TX платы |
| TX | RX платы |
| GND | GND |

- Уровень логики UART у плат JBD обычно **3,3 В**. Перед подключением сверьтесь с документацией
  именно вашей платы: адаптер на 5 В может повредить плату.
- В Windows адаптер появится как `COM3`, `COM4` и т. п.; в Linux — как `/dev/ttyUSB0` или `/dev/ttyACM0`.
- Не знаете, какой порт занят батареей? Нажмите в программе «Найти батарею» или см. [`docs/kak-najti-port.md`](docs/kak-najti-port.md).

## Важно про плату и напряжение

Программа не проверяет напряжение системы по модели платы — это делаете вы.
Для батареи **12S** (12 последовательных ячеек, номинально около 38,4 В, полный заряд около 43,8 В)
плата должна быть рассчитана на 12 ячеек. Например, JBD SP14S004 поддерживает 7–14S и подходит
для 12S. Перед работой сверьте модель платы и число ячеек (регистр «Число ячеек» на экране
настроек должен показывать 12) с паспортом. Число ячеек из приложения не меняется.

## Установка на Windows 10/11

Установите [Git](https://git-scm.com/download/win) и [Node.js 20+](https://nodejs.org/), затем выполните:

```powershell
git clone https://github.com/danilka-revin/ploter_a1.git
cd ploter_a1\jbd-bms-app
.\install-windows.cmd
```

Будут установлены зависимости, собран интерфейс и создан ярлык **JBD BMS** на рабочем столе.
Последующий запуск — ярлыком или `run-windows.cmd`. Если USB–UART не появился в списке,
установите драйвер производителя адаптера (CH340, CP210x или FTDI) и переподключите его.

## Установка на Ubuntu

Нужны Ubuntu 22.04 / 24.04 (или совместимый Debian-подобный дистрибутив) и доступ в интернет.

```bash
git clone https://github.com/danilka-revin/ploter_a1.git
cd ploter_a1/jbd-bms-app
bash install-ubuntu.sh
```

Установщик:
- ставит Node.js 24 LTS, git, если их нет (спросит пароль администратора);
- загружает библиотеки и собирает программу;
- добавляет вас в группу `dialout`, чтобы программа видела `/dev/ttyUSB*`;
- создаёт ярлык в меню приложений и команду `jbd-bms`.

**После установки выйдите из системы и войдите снова** (или перезагрузите компьютер) —
иначе группа `dialout` не применится и порт будет недоступен.

Ubuntu может сам занимать новые USB-UART адаптеры через службу ModemManager.
Если порт открывается, но ответа от платы нет, выполните:

```bash
sudo systemctl disable --now ModemManager
```

## Запуск

- Из меню приложений: «JBD BMS — чтение и прошивка».
- Из терминала: `jbd-bms` или `bash run.sh` в папке `jbd-bms-app`.
- В браузере: <http://127.0.0.1:8585> (порт меняется переменной `BMS_APP_PORT`).

`run.sh` при каждом запуске:
1. проверяет GitHub и, если в ветке `main` появился новый коммит с программой, обновляет её;
2. при изменении библиотек выполняет `npm ci`, а при изменении интерфейса — сборку;
3. запускает локальный сервер и открывает браузер.

Сервер слушает только `127.0.0.1` — плата доступна только с этого компьютера.
Журнал работы: `node_modules/.cache/jbd-bms.log`.

## Запись настроек

Вкладка **«Защита и настройки»** плитки «Плата» позволяет изменить:

- **ёмкость** — номинальная ёмкость батареи (мАч);
- **токи** — пороги защиты от перегрузки по заряду и по разряду (мА). Это пороги срабатывания
  защиты платы, а не уставки зарядника;
- **напряжения** — перенапряжение и понижение ячеек и батареи, пороги возврата;
- **температуры** — пороги перегрева и переохлаждения при заряде и разряде, пороги возврата;
- **балансировку** — порог старта и окно.

Как работает запись:
1. Приложение проверяет каждое значение: допустимый диапазон и шаг регистра (например,
   напряжение батареи — кратно 10 мВ).
2. Проверяются связи порогов: срабатывание должно быть выше возврата (например, перенапряжение
   ячейки выше возврата после него), иначе запись не выполняется.
3. Перед записью показывается список «было → станет». Нужна галочка «я проверил(а) значения»
   и пароль платы, если он задан на плате. Счётчик напротив вкладки показывает, сколько полей
   уже изменено; запись идёт только этих полей.
4. Запись идёт одной операцией в заводском режиме платы (как в проекте bms-tools): пароль,
   вход, запись, выход. Если запись прервалась, выход делается **без сохранения**, чтобы не
   закрепить частичные значения.
5. После записи каждое значение перечитывается с платы и сравнивается с введённым.

Помимо основных порогов доступны таблица SOC (11 точек), задержки срабатывания и возврата
(регистры 0x3A–0x3F, каждое поле — свой байт одного регистра), время свечения индикатора,
время выключения ключей, маски функций платы и датчиков температуры. Рискованные регистры
(0x13 пустое напряжение, аппаратные пороги, маски) требуют отдельного подтверждения — иначе
плата может перестать отдавать ток или отключить нагрузку.

Число ячеек, пароли, калибровка и регистры, которых нет в списке, из приложения не меняются.

Сбросы счётчиков и ключи описаны по bms-tools; на вашей плате их стоит проверить на безопасных значениях.

> **Внимание.** Неверные пороги могут отключить защиту аккумулятора или вызвать ложные срабатывания.
> Перед первой записью перепишите текущие значения с экрана настроек: так их можно будет вернуть вручную.

## Управление

Все действия требуют подтверждения: кнопка сначала показывает «точно?», повторное нажатие выполняет.
Ключи и остаток ёмкости пишутся без сохранения в память платы — после перезагрузки платы значения
вернутся из EEPROM.

- **Ключи заряда и разряда** — выключить или включить заряд и разряд. Выключенный разряд отключает
  нагрузку от батареи.
- **Остаток ёмкости** — задать текущий остаток в ампер-часах (не больше полной ёмкости).
- **Счётчики ошибок** — сброс счётчиков срабатываний защит. Сохраняется в память платы.
- **Резервная копия** — сохранить все настройки (включая таблицу SOC и маски) в файл JSON и
  восстановить их. Перед записью показывается список «сейчас → из копии». Число ячеек и параметры
  вне списка записи пропускаются.
- **Пересчёт SOC и мягкая перезагрузка** — помечены как рискованные: нужен второй подтвержающий
  флаг, перезагрузка прервёт связь с платой.
- **Балансировка (0xE2)** — команда подтверждена по открытым описаниям, но не проверялась на
  железе: она тоже требует явного согласия.

Калибровку напряжений, токов и температур, тест балансировки и смену пароля приложение не делает:
для них нужны эталонные приборы или они могут закрыть доступ к плате.

## Обновление из GitHub

Как в linux_pcb_app:
- при открытии программы и каждые 30 минут она проверяет последний коммит ветки `main`;
- если коммит новее установленного, в шапке появляется кнопка обновления;
- кнопка «Обновить с main» делает: `git fetch` → `git merge --ff-only` → `npm ci` (если
  изменились библиотеки) → сборку → перезапуск сервера.

Обновление **не выполняется**, если:
- в папке программы есть несохранённые локальные изменения;
- выбрана ветка, отличная от `main`;
- папка не является клоном репозитория.

В таких случаях программа сообщает причину и ничего не трогает.
Адрес репозитория и ветка задаются в `update.json` (по умолчанию `danilka-revin/ploter_a1`, ветка `main`).

## Что нужно, чтобы включить прошивку

Чтобы программа смогла записать `.hex`, нужны:
1. подтверждённый протокол загрузки прошивки по UART для конкретной модели платы
   (открытых описаний для JBD нет, а неверный файл может вывести плату из строя);
2. лог обмена с официальной утилитой **JBDTools** при прошивке, снятый на вашей плате;
3. точная модель платы и число ячеек.

Пока эти данные не получены, функция записи остаётся отключённой, и это не ошибка.

## Разработка

```bash
npm install
npm run dev        # интерфейс с горячей перезагрузкой (порт 5173)
npm run build      # проверка типов и сборка
npm test           # тесты протокола, банков, HTTP API, Intel HEX, клиента, обновления и панели
npm run test:fast  # только протокол, карта регистров и менеджер банков
```

Структура:

```

install-ubuntu.sh      установка на Ubuntu, ярлык, группа dialout

  server.mjs           локальный сервер: интерфейс, API панели, обновление
  jbd-protocol.mjs     кадры протокола JBD, карта 59 регистров EEPROM, каталог регистров, пределы

  banks.mjs            менеджер банков: параллельный опрос, история, итоги парка, отчёт и CSV
```
