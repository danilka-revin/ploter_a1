# JBD BMS — чтение и прошивка

Программа для Ubuntu: читает данные с платы BMS JBD / Xiaoxiang / Overkill Solar по UART
(последовательный порт 9600 8N1) и показывает их в браузере на локальном адресе.
Оформление и механизм обновления из GitHub такие же, как в проекте
[linux_pcb_app](https://github.com/danilka-revin/linux_pcb_app).

> **Прошивка.** Экран «Прошивка» проверяет файл `.hex` (разбор, адреса, контрольные суммы,
> размер, SHA-256). **Запись в плату пока отключена**: открытого протокола загрузки прошивки
> по UART у JBD нет в открытом доступе, поэтому кнопка «Записать прошивку» заблокирована.
> Запись появится после того, как будет подтверждён протокол загрузки (см. раздел «Что нужно,
> чтобы включить прошивку»).

## Что умеет

| Экран | Что показывает |
|---|---|
| Обзор | напряжение, ток, заряд (Ач и %), циклы, дата производства, температуры, состояние ключей заряда и разряда, защиты, активные балансировки |
| Ячейки | напряжение каждой ячейки, шкала 2,50–3,65 В, минимум, максимум, разброс; разброс больше 30 мВ подсвечивается |
| Защиты и настройки | пороги защит, ёмкость, токи, балансировка, температурные пороги. Можно **изменить и записать в плату** (см. раздел «Запись настроек») |
| Прошивка | версия прошивки (регистр 0x03), выбор и проверка файла `.hex` |

Данные обновляются автоматически, пока плата подключена. Есть демо-режим без платы:
в списке портов выберите «Демо-режим (без платы)».

## Подключение платы

Нужен USB–UART адаптер (CP2102, CH340, FTDI и т. п.).

| Адаптер | Плата BMS |
|---|---|
| RX | TX платы |
| TX | RX платы |
| GND | GND |

- Уровень логики UART у плат JBD обычно **3,3 В**. Перед подключением сверьтесь с документацией
  именно вашей платы: адаптер на 5 В может повредить плату.
- Адаптер появится как `/dev/ttyUSB0` или `/dev/ttyACM0`.

## Важно про плату и напряжение

Программа не проверяет напряжение системы по модели платы — это делаете вы.
Для батареи **12S** (12 последовательных ячеек, номинально около 38,4 В, полный заряд около 43,8 В)
плата должна быть рассчитана на 12 ячеек. Например, JBD SP14S004 поддерживает 7–14S и подходит
для 12S. Перед работой сверьте модель платы и число ячеек (регистр «Число ячеек» на экране
настроек должен показывать 12) с паспортом. Число ячеек из приложения не меняется.

## Установка на Ubuntu

Нужны Ubuntu 22.04 / 24.04 (или совместимый Debian-подобный дистрибутив) и доступ в интернет.

```bash
git clone https://github.com/danilka-revin/ploter_a1.git
cd ploter_a1/jbd-bms-app
bash install-ubuntu.sh
```

Установщик:
- ставит Node.js 24 LTS, git, если их нет (спросит пароль администратора);
- загружает библиотеки и собирает программу;
- добавляет вас в группу `dialout`, чтобы программа видела `/dev/ttyUSB*`;
- создаёт ярлык в меню приложений и команду `jbd-bms`.

**После установки выйдите из системы и войдите снова** (или перезагрузите компьютер) —
иначе группа `dialout` не применится и порт будет недоступен.

Ubuntu может сам занимать новые USB-UART адаптеры через службу ModemManager.
Если порт открывается, но ответа от платы нет, выполните:

```bash
sudo systemctl disable --now ModemManager
```

## Запуск

- Из меню приложений: «JBD BMS — чтение и прошивка».
- Из терминала: `jbd-bms` или `bash run.sh` в папке `jbd-bms-app`.
- В браузере: <http://127.0.0.1:8585> (порт меняется переменной `BMS_APP_PORT`).

`run.sh` при каждом запуске:
1. проверяет GitHub и, если в ветке `main` появился новый коммит с программой, обновляет её;
2. при изменении библиотек выполняет `npm ci`, а при изменении интерфейса — сборку;
3. запускает локальный сервер и открывает браузер.

Сервер слушает только `127.0.0.1` — плата доступна только с этого компьютера.
Журнал работы: `node_modules/.cache/jbd-bms.log`.

## Запись настроек

Экран «Защиты и настройки» позволяет изменить:

- **ёмкость** — номинальная ёмкость батареи (мАч);
- **токи** — пороги защиты от перегрузки по заряду и по разряду (мА). Это пороги срабатывания
  защиты платы, а не уставки зарядника;
- **напряжения** — перенапряжение и понижение ячеек и батареи, пороги возврата;
- **температуры** — пороги перегрева и переохлаждения при заряде и разряде, пороги возврата;
- **балансировку** — порог старта и окно.

Как работает запись:
1. Приложение проверяет каждое значение: допустимый диапазон и шаг регистра (например,
   напряжение батареи — кратно 10 мВ).
2. Проверяются связи порогов: срабатывание должно быть выше возврата (например, перенапряжение
   ячейки выше возврата после него), иначе запись не выполняется.
3. Перед записью показывается список «было → станет». Нужна галочка «я проверил(а) значения»
   и пароль платы, если он задан на плате.
4. Запись идёт одной операцией в заводском режиме платы (как в проекте bms-tools): пароль,
   вход, запись, выход. Если запись прервалась, выход делается **без сохранения**, чтобы не
   закрепить частичные значения.
5. После записи каждое значение перечитывается с платы и сравнивается с введённым.

Число ячеек, прошивка и регистры, которых нет в списке, из приложения не меняются.

> **Внимание.** Неверные пороги могут отключить защиту аккумулятора или вызвать ложные срабатывания.
> Перед первой записью перепишите текущие значения с экрана настроек: так их можно будет вернуть вручную.

## Обновление из GitHub

Как в linux_pcb_app:
- при открытии программы и каждые 30 минут она проверяет последний коммит ветки `main`;
- если коммит новее установленного, в шапке появляется кнопка обновления;
- кнопка «Обновить с main» делает: `git fetch` → `git merge --ff-only` → `npm ci` (если
  изменились библиотеки) → сборку → перезапуск сервера.

Обновление **не выполняется**, если:
- в папке программы есть несохранённые локальные изменения;
- выбрана ветка, отличная от `main`;
- папка не является клоном репозитория.

В таких случаях программа сообщает причину и ничего не трогает.
Адрес репозитория и ветка задаются в `update.json` (по умолчанию `danilka-revin/ploter_a1`, ветка `main`).

## Что нужно, чтобы включить прошивку

Чтобы программа смогла записать `.hex`, нужны:
1. подтверждённый протокол загрузки прошивки по UART для конкретной модели платы
   (открытых описаний для JBD нет, а неверный файл может вывести плату из строя);
2. лог обмена с официальной утилитой **JBDTools** при прошивке, снятый на вашей плате;
3. точная модель платы и число ячеек.

Пока эти данные не получены, функция записи остаётся отключённой, и это не ошибка.

## Разработка

```bash
npm install
npm run dev        # интерфейс с горячей перезагрузкой (порт 5173)
npm run build      # проверка типов и сборка
npm test           # тесты протокола, Intel HEX, клиента, обновления и интерфейса
```

Структура:

```
run.sh                 запуск (обновление, сборка, сервер, браузер)
install-ubuntu.sh      установка на Ubuntu, ярлык, группа dialout
scripts/
  server.mjs           локальный сервер: интерфейс, API, обновление
  jbd-protocol.mjs     кадры протокола JBD (0xDD … 0x77, контрольная сумма)
  bms-client.mjs       чтение регистров и расчёт сведений о ячейках
  serial-transport.mjs последовательный порт 9600 8N1
  fake-bms.mjs         имитатор платы для демо и тестов
  intel-hex.mjs        разбор файлов .hex
  firmware.mjs         проверка прошивки (запись — заглушка до подтверждения протокола)
  updater.mjs          обновление из GitHub
src/                   интерфейс React
test/                  тесты
```
